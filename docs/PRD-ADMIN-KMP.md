# 1. 产品定位

KMP 管理端是瑜伽馆老板和员工每天使用的“经营驾驶舱”。

它不是把 Web 后台缩小到手机上，而是围绕移动场景重新设计：

> **打开 App → 先看到今天最重要的事 → 处理待办 → 完成经营动作 → 查看结果。**

核心目标：

- 少看报表，多做动作；
- 少记 Excel，多用会员档案；
- 少靠微信聊天，多用任务；
- 少凭感觉排课，多看数据；
- 少卖单一课程，多经营会员 LTV。

# 5. 待办与预警

## 5.1 待办来源

系统根据业务事件自动产生：

- 新体验预约；
- 体验完成待跟进；
- 会员即将到期；
- 沉默会员；
- 爽约会员；
- 高价值会员；
- 训练计划未完成；
- 商品缺货；
- 课程低上座率；
- 售后申请。

## 5.2 任务状态

```text
待处理 → 处理中 → 已完成
                 ↘ 已忽略
```

完成时必须记录结果。

例如：

```text
会员：张某
原因：14天未训练
动作：已联系
结果：本周恢复训练
下次跟进：2026-08-25
```

## 5.3 预警

预警与待办不同：

- 待办：需要人做事情；
- 预警：经营指标出现异常。

例如：

> 本月私教转化率较上月下降 20%。

页面必须给出：

- 影响范围；
- 可能原因；
- 可查看的数据；
- 建议动作。

# 10. 课程与排课

## 10.1 课程模板

字段：

- 名称；
- 类型；
- 难度；
- 时长；
- 容量；
- 教练；
- 教室；
- 消耗规则；
- 价格；
- 会员限制。

## 10.2 排课

支持：

- 单次排课；
- 周期排课；
- 复制；
- 调课；
- 取消课程。

排课时检查：

- 教练时间冲突；
- 教室冲突；
- 容量；
- 是否满足会员规则。

## 10.3 排课建议

系统根据历史数据提示：

```text
连续4周上座率 ≥ 85%
→ 建议增加场次

连续4周上座率 ≤ 40%
→ 建议减少/调整时间
```

最终由店长确认，不自动修改排课。

# 11. 签到与核销

## 11.1 签到

支持：

- 用户签到码；
- 前台核销；
- 管理端手动签到。

## 11.2 签到后动作

```text
签到成功
→ 更新预约
→ 扣减权益
→ 增加训练次数
→ 增加积分
→ 更新连续训练
→ 判断运营规则
```

## 11.3 异常

- 重复签到；
- 无有效权益；
- 预约不存在；
- 已取消；
- 已爽约。

异常需要人工确认权限。

- 删除订单。

所有敏感操作记录：

- 操作人；
- 时间；
- 原值；
- 新值；
- 原因。

# 26. 管理端验收原则

一个管理功能完成的标准不是“页面能打开”，而是：

1. 能看到业务对象；
2. 能理解为什么要处理；
3. 能完成核心操作；
4. 操作结果立即可见；
5. 关键动作有权限控制；
6. 敏感操作有日志；
7. 需要会员运营时能生成任务；
8. 经营结果能进入数据统计。
