# Yoga KMP 移动管理端 PRD V7.0

> **目标用户**：老板、店长、前台、教练  
> **技术**：Kotlin Multiplatform / Compose Multiplatform + Spring Boot  
> **形态**：只做移动管理端，不做 Web 后台。  
> **核心思想**：管理端不是“功能菜单”，而是“今天应该做什么”的经营工作台。

---

# 1. 管理端核心闭环

```text
业务事件
→ 系统判断
→ 创建运营任务
→ KMP提醒
→ 员工处理
→ 记录结果
→ 下一步任务
→ 数据统计
→ 老板复盘
```

例如：

```text
会员14天未训练
→ 系统创建召回任务
→ 前台看到任务
→ 查看会员历史
→ 联系会员
→ 记录“工作忙”
→ 推荐线上训练
→ 设定7天后复查
→ 用户恢复训练
→ 任务关闭
```

# 2. 角色权限

## 老板

看经营结果、收入、成本、会员、商品、员工任务；可以调整核心经营配置。

## 店长

负责全部日常运营、会员、排课、销售、商品、任务、数据。

## 前台

接待、签到、预约、订单、商品、体验客户跟进。

## 教练

排课、签到查看、会员训练记录、体验反馈、私教、小班、数字内容。

权限必须由服务端校验，客户端隐藏菜单不能作为安全边界。

# 13. 沉默会员召回

触发：默认14天无训练。

处理：

```text
查看会员历史
→ 判断原因
→ 联系
→ 选择原因标签
→ 推荐解决方案
→ 设置跟进
```

原因：工作忙、时间不合适、课程不喜欢、价格、教练、身体不适、其他。

解决方案：

```text
时间少 → 20分钟线上训练
课程不喜欢 → 推荐其他课程
不知道练什么 → 训练计划
价格 → 低门槛产品
```

# 14. 私教

## 套餐

管理：次数、价格、有效期、适用教练、退款规则。

## 预约

教练可设置可预约时间；系统检查冲突。

## 训练记录

每节私教必须有：

- 本次训练
- 用户反馈
- 下次计划

## 复购

剩余20%自动产生任务；不是直接“催续费”，而是先要求教练完成阶段复盘。

# 19. 商品

## 商品

## SKU

## 库存

# 26. 关键指标定义

### 体验转化率

`体验后完成正式购买人数 / 完成体验人数`

### 续费率

`到期周期内完成续费人数 / 进入续费周期人数`

### ARPU

`周期总收入 / 周期活跃付费用户数`

### 商品联购率

`购买服务后同时购买商品人数 / 购买服务人数`

### 运营任务完成率

`按期完成任务 / 到期任务`

指标口径必须固定，不允许不同页面用不同公式。

# 28. 离线与网络异常

管理端不能假设永远在线。

查询类页面可以显示缓存，但：

- 签到
- 退款
- 改库存
- 改价格
- 关闭课程
- 处理任务

必须联网成功后才确认完成。

---

# 29. 幂等要求

以下操作必须幂等：

- 签到
- 消课
- 支付回调
- 退款
- 发放积分
- 发放推荐奖励
- 发放会员权益
- 库存扣减

重复请求不能造成重复业务结果。

# 30. KMP 页面结构原则

移动端不照搬 Web 表格。

优先：

```text
今日任务
→ 卡片
→ 用户详情
→ 快速动作
```

复杂数据采用：

- 筛选抽屉
- Tab
- 卡片
- Bottom Sheet
- 二次确认

高频操作必须 3 步以内完成。

---

# 31. 验收标准

每个模块必须有：

```text
正常流程
异常流程
权限
状态机
接口
幂等
操作日志
消息
数据指标
```

例如签到：

1. 有预约可以签到。
2. 无预约按规则处理。
3. 重复签到不重复扣课。
4. 签到失败有原因。
5. 扣课失败不能显示签到成功。
6. 成功后用户端立即可见。
7. 产生训练记录。
8. 触发积分/运营规则。
