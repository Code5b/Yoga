# Yoga 单店经营与会员运营系统 PRD V5.1

> 更新时间：2026-08-19  
> 产品阶段：单店 MVP → 单店增长版  
> 产品形态：微信小程序（uni-app）+ 移动管理端（KMP）+ Spring Boot 后端  
> 当前原则：不做 SaaS、不做多门店、不做 Web 管理后台、不做开放平台，先把一家瑜伽馆的经营闭环跑通。

---

## 1. 产品定位

Yoga 不是简单的“瑜伽约课小程序”，而是一套面向单店瑜伽馆的**经营与会员增长系统**。

核心经营闭环：

```text
获客
 ↓
体验
 ↓
转化
 ↓
团课/小班/私教
 ↓
训练与会员活跃
 ↓
体态评估/训练计划
 ↓
数字课程/直播训练营
 ↓
瑜伽商品
 ↓
续费/VIP
 ↓
转介绍
 ↓
新客
```

### 1.1 核心目标

1. 提升体验课 → 会员转化率
2. 提升会员到店频率与训练活跃度
3. 提升 ARPU 与 LTV
4. 增加私教、小班、评估、工作坊等高毛利服务
5. 增加瑜伽商品与数字内容收入
6. 降低会员流失
7. 让店长每天知道“应该做什么”
8. 让教练的课时、会员服务和销售贡献可量化

### 1.2 非目标

当前版本明确不做：

- SaaS 多租户
- 多门店
- 门店加盟管理
- Web 管理后台
- 开放 API 平台
- 外部教练市场
- 大规模供应链平台
- 复杂 ERP
- 复杂财务系统

# 2. 技术与终端边界

## 2.1 技术栈

| 层 | 技术 | 定位 |
|---|---|---|
| 用户端 | uni-app | 微信小程序为第一优先级，可保留 H5/App 扩展能力 |
| 管理端 | Kotlin Multiplatform / Compose Multiplatform | 店长、前台、教练移动端 |
| 后端 | Spring Boot | REST API、业务逻辑、任务、支付、运营 |
| 数据库 | MySQL | 核心业务数据 |
| 缓存 | Redis | 登录态、库存、预约并发、短期缓存、任务锁 |
| 文件/视频 | 对象存储 | 图片、课程视频、直播回放 |
| 消息 | 微信订阅消息 + 应用内消息 | 预约、到期、运营任务、训练提醒 |

> 具体基础设施可在技术设计阶段确定，但产品 PRD 不引入额外必选技术栈。

```text

训练营未打卡
```

- 会员流失风险
- 商品库存不足
- 退款异常
- 体验转化下降
- 续费率下降

# 11. 数字课程

## 11.1 产品定位

数字课程不是“视频商城”，而是：

> **训练结果产品 + 线下会员留存工具 + 增量收入渠道。**

## 11.2 内容形态

### 单节录播

¥9.9-29.9。

### 7/21/30 天训练计划

示例：

- 7 天肩颈：¥39-99
- 21 天柔韧：¥99-199
- 30 天入门：¥129-299

### 直播

每周 2-3 场，每场 45-60 分钟；直播后沉淀回放。

### 训练营

¥299-599，包含录播、直播、打卡、答疑、动作纠正、结营报告。

## 11.3 内容生产

阶段一：教练手机自制 MVP。  
阶段二：验证销量后专业重制爆款。  
阶段三：成熟后再引入外部教练合作。

不要求第一期建设复杂内容平台。

## 11.4 训练任务模型

```text
购买计划

 ↓
提醒
 ↓

 ↓
打卡
```

# 20. 核心原则

1. **先做单店闭环，再考虑 SaaS。**
2. **后台只做 KMP 移动端，不建设 Web 管理后台。**
3. **数字课程卖的是训练结果，不是视频文件。**
4. **商品必须和课程、训练、会员运营联动。**
5. **运营任务必须能落到具体动作。**
