# V8 PRD 对齐与范围收缩

本文件用于约束 V7 产品文档进入工程实现时的范围，避免 PRD 继续无边界扩张。

## 1. P0：交易与履约基础

```text
微信登录
 ↓
会员
 ↓
会员产品
 ↓
订单/支付
 ↓
Entitlement
 ↓
课程/排课
 ↓
Booking
 ↓
签到
 ↓
Entitlement Consume
```

P0 任何一个环节不能只做 UI；必须同时有 API、状态机、异常、幂等、权限、流水和验收用例。

## 2. P1：单店经营基本盘

优先建设不依赖内容生产的人力友好型经营能力：

- 体验 CRM
- 续费
- 沉默召回
- 私教
- 精品小班
- 商品/SKU/库存
- 基础经营数据
- Event → Rule → Task

**P1 明确不做数字课程。**

核心目标是先验证：会员留存、客单价、私教/小班渗透率、商品连带率和续费。

## 3. P2：运营自动化与 LTV 增长

- 运营规则与任务自动化
- Next Best Action 推荐
- 商品套餐
- 推荐有礼
- 更完整的会员生命周期运营
- 工作坊等线下增收产品

**P2 仍然不要求数字课程。**

这一阶段重点是提高单店运营效率，而不是增加内容生产负担。

## 4. P3：数字课程与线上增收

数字课程统一推迟到 **P3**，作为门店经营成熟后的第二增长曲线。

P3 才开始建设：

- 7/14/21 天训练计划
- 录播数字课程
- 数字内容版本管理
- 训练计划权益
- 直播/训练营
- 数字课程与线下课程联动

### 数字课程的进入条件

必须先具备：

- 稳定会员规模
- 稳定课程体系
- 稳定教练团队
- 可持续的内容运营人员/时间
- 已经验证的高需求线下课程

原则：**先在线下验证课程，再把爆款课程标准化、录制和数字化。**

不要求在 P0/P1/P2 阶段提前建设完整内容生产体系。

## 5. 商品策略

商城第一阶段不是独立电商，而是“训练驱动的商品增购”。

```text
训练目标
 ↓
线下训练
 ↓
会员需求
 ↓
推荐辅助用品
 ↓
商品购买
```

P1/P2 先做好商品、SKU、库存、订单、发货和基础售后；数字课程暂不作为商品推荐的前置条件。

## 6. 推荐策略

P2 第一阶段不做 AI。

采用可运营规则：

```text
训练目标 + 行为 + 会员状态 + 已购内容
                     ↓
                Rule Engine
                     ↓
                Next Best Action
```

必须具备去重、频控、命中记录和效果统计。

## 7. 退款策略

套餐退款不是简单的订单比例退款。必须按 OrderItem、已使用权益、商品履约状态和优惠分摊计算。

涉及数字内容的退款规则留到 P3 数字产品上线时一起实现；P0/P1 先保证线下会员、课程、私教、小班和商品交易链路。

## 8. 暂缓功能

以下功能保留在产品规划中，但不阻塞单店 MVP：

- SaaS
- 多门店
- 多租户
- 企业瑜伽
- Retreat
- AI 推荐
- P3 之前的数字课程
- P3 之前的复杂直播体系
- 复杂积分体系
- 复杂营销中心
- 微服务

## 9. 产品完成定义

一个功能只有同时满足以下条件才算完成：

```text
入口
+ 正常流程
+ 异常流程
+ 状态机
+ API
+ 权限
+ 幂等
+ 数据流水
+ Event
+ 埋点
+ 运营触发
+ 验收用例
```

## 10. 经营验证优先级

优先验证：

1. 用户愿意持续训练；
2. 会员愿意续费；
3. 训练能够带来小班/私教增购；
4. 商品能够带来连带购买；
5. 运营任务能够改善上述指标；
6. **P3 再验证数字课程是否能够形成第二增长曲线。**

> 不以“功能数量”作为产品成功标准，以“单店收入、人效和会员 LTV 是否改善”作为核心标准。
