# V8 PRD 对齐与范围收缩

本文件用于约束 V7 产品文档进入工程实现时的范围，避免 PRD 继续无边界扩张。

## 1. P0 必须形成完整闭环

```text
微信登录
 ↓
会员
 ↓
会员产品
 ↓
订单/支付
 ↓
Entitlement
 ↓
课程/排课
 ↓
Booking
 ↓
签到
 ↓
Entitlement Consume
```

P0 任何一个环节不能只做 UI；必须同时有 API、状态机、异常、幂等、权限、流水和验收用例。

## 2. P1 才开始做经营自动化

体验 CRM、续费、沉默召回、私教、小班、商品、库存、数字课程统一建立在 P0 交易与会员数据之上。

核心自动化：

```text
Event → Rule → CRMTask
```

## 3. 数字课程策略

第一阶段不要求直播。

先建设可录播、可版本化的训练内容：

- 7 天训练
- 14 天训练
- 21 天训练

用户购买的是训练结果对应的计划/权益，而不是单纯的视频列表。

内容必须版本化，已购买用户绑定历史版本。

## 4. 商品策略

商城第一阶段不是独立电商，而是“训练驱动的商品增购”。

```text
训练目标
 ↓
训练计划
 ↓
推荐辅助用品
 ↓
商品购买
```

第一阶段只需要商品、SKU、库存、订单、发货和基础售后。

## 5. 推荐策略

第一阶段不做 AI。

采用可运营规则：

```text
训练目标 + 行为 + 会员状态 + 已购内容
                     ↓
                Rule Engine
                     ↓
                Next Best Action
```

必须具备去重、频控、命中记录和效果统计。

## 6. 退款策略

套餐退款不是简单的订单比例退款。必须按 OrderItem、已使用权益、数字内容访问状态、商品履约状态和优惠分摊计算。

因此退款能力属于 P1/P2 的高风险模块，应在数据库和领域模型稳定后开发。

## 7. 暂缓功能

以下功能保留在产品规划中，但不阻塞单店 MVP：

- SaaS
- 多门店
- 多租户
- 企业瑜伽
- Retreat
- AI 推荐
- 复杂直播体系
- 复杂积分体系
- 复杂营销中心

## 8. 产品完成定义

一个功能只有同时满足以下条件才算完成：

```text
入口
+ 正常流程
+ 异常流程
+ 状态机
+ API
+ 权限
+ 幂等
+ 数据流水
+ Event
+ 埋点
+ 运营触发
+ 验收用例
```

## 9. 经营验证优先级

优先验证：

1. 用户愿意持续训练；
2. 会员愿意续费；
3. 训练能够带来小班/私教增购；
4. 训练能够带来数字产品和商品增购；
5. 运营任务能够改善上述指标。

> 不以“功能数量”作为产品成功标准，以“单店收入和会员 LTV 是否改善”作为核心标准。
