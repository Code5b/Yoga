# Yoga 用户端 PRD V7.0

> **定位**：单店瑜伽馆用户经营与消费入口  
> **技术**：uni-app + 微信小程序 + Spring Boot  
> **目标**：每个核心功能必须形成“入口 → 判断 → 操作 → 状态 → 结果 → 通知 → 数据 → 运营动作”的完整闭环。

---

# 1. 产品原则

用户端不是约课工具，而是用户生命周期产品：

```text
获客 → 体验 → 首购 → 训练 → 增购 → 复购 → 续费 → 推荐
```

所有金额、库存、预约名额、会员权益、次数和订单状态以服务端为准。

---

# 2. 用户生命周期

| 状态 | 进入条件 | 核心目标 | 产品动作 |
|---|---|---|---|
| 游客 | 未登录 | 注册/体验 | 内容、课程、体验课 |
| 新用户 | 完成注册 | 首次消费 | 体验课/新手计划 |
| 体验用户 | 买体验课 | 到店 | 预约、提醒、签到 |
| 新会员 | 首购会员 | 形成习惯 | 首周课程推荐 |
| 活跃会员 | 持续训练 | 增购 | 小班、私教、数字 |
| 沉默会员 | ≥14天无训练 | 召回 | 线上训练、课程推荐 |
| 到期会员 | ≤30天到期 | 续费 | 个性化续费 |
| 流失会员 | 到期且无消费 | 召回 | 低门槛产品/活动 |
| 高价值会员 | 高消费/高活跃 | LTV | VIP、私教、工作坊 |

# 4. 登录注册闭环

## 4.1 流程

```text
启动
→ 本地Token检查
→ 无Token：微信登录
→ 服务端创建/查找用户
→ 判断是否绑定手机号
→ 判断会员状态
→ 首页
```

## 4.2 数据

用户：微信身份、手机号、昵称、头像、注册时间、来源、推荐人。

## 4.3 异常

- 网络失败：显示重试。
- 登录过期：静默刷新，失败后重新登录。
- 用户取消授权：保留游客浏览能力。
- 重复登录：禁止重复创建会员。

## 4.4 验收

同一个微信身份永远对应同一个用户；所有订单/预约只能绑定一个用户。

# 5. 首页

## 5.1 第一屏规则

优先级：

1. 上课提醒/待完成训练；
2. 会员权益；
3. 今日课程；
4. 推荐；
5. 活动/商城。

## 5.2 会员卡片

显示：卡名称、状态、剩余次数、到期日期。

### 状态文案

- 正常：`还有 12 次课，8月30日到期`
- 次数不足：`还剩 1 次，建议提前规划`
- 7天到期：`还有 7 天到期`
- 已到期：`会员已到期，重新激活训练`

点击进入会员权益页。

## 5.3 今日训练

有训练计划时优先展示计划；没有计划则展示推荐课。

完成训练后：

```text
完成
→ 服务端记录
→ 防重复完成
→ 更新计划进度
→ 更新连续训练
→ 发积分
→ 推荐下一课
```

## 5.4 推荐

第一阶段规则引擎：

```text
新用户 → 体验课
新会员 → 新手计划
高频 → 小班/私教
14天未训练 → 线上短课
购买柔韧 → 瑜伽砖/瑜伽带
即将到期 → 续费方案
高价值 → VIP/工作坊
```

每条推荐必须说明理由，避免纯广告感。

# 7. 预约功能闭环

## 7.1 点击预约

服务端按顺序校验：

```text
用户有效
→ 课程有效
→ 未结束
→ 未超过预约截止
→ 有可用权益
→ 无重复预约
→ 无时间冲突
→ 有余位
→ 未被限制
```

## 7.2 成功

```text
创建预约
→ 原子占用名额
→ 创建权益使用记录
→ 返回预约号
→ 页面展示成功
→ 发送提醒
```

## 7.3 满员

> “这节课已经满员，可以加入候补。有人取消时，我们会按顺序通知。”

候补：第一候补获得临时锁定；超过确认时间自动释放。

## 7.4 重复预约

> “你已经预约了这节课，无需重复操作。”

## 7.5 时间冲突

> “你在这个时间已经有另一节课程，请先取消原预约或选择其他场次。”

## 7.6 无权益

> “当前会员权益不能预约这节课，你可以购买对应课程权益。”

## 7.7 取消

取消前显示实际规则：

> “距离开课还有 3 小时，取消后将退回/扣除 1 次，请确认。”

不能由前端计算规则。

# 8. 签到与消课

```text
预约
→ 到店
→ 扫码/前台签到
→ 服务端校验
→ 签到
→ 核销权益
→ 生成训练记录
→ 积分
→ 连续训练
→ 评价
```

重复签到：不重复扣课。

课程取消：恢复权益并通知用户。

爽约：按门店规则产生爽约记录。

# 9. 会员产品购买

产品类型：体验课、单次课、次卡、月卡、季卡、年卡、私教、小班、训练计划、课程+商品套餐。

详情必须展示：价格、有效期、次数、适用范围、时间限制、赠送权益、退款规则。

支付闭环：

```text
确认产品
→ 服务端重新报价
→ 创建订单
→ 微信支付
→ 支付回调
→ 幂等发放权益
→ 订单完成
→ 用户可立即使用
```

支付成功但前端断网：重新打开订单必须从服务端查询，不得重复支付。

# 11. 私教/小班/评估

## 私教

```text
查看教练
→ 查看专长
→ 查看可预约时间
→ 购买/使用套餐
→ 预约
→ 上课
→ 教练记录
→ 用户查看

```

## 精品小班

展示周期、主题、教练、容量、已报名、剩余席位、价格。购买后自动生成对应权益。

## 体态评估

```text
购买
→ 预约
→ 到店
→ 教练评估
→ 报告
→ 训练方向
→ 推荐课程/私教/数字训练
```

报告不能做医疗诊断。

# 12. 数字训练

数字产品分三类：

1. 单节课；
2. 7/21/30天训练计划；
3. 直播/训练营。

## 12.1 单节课

播放前校验购买权限；播放过程中记录进度；达到完成阈值后允许完成。

## 12.2 训练计划

```text
购买
→ 自动生成计划
→ 每日任务
→ 开始
→ 训练
→ 完成
→ 打卡
→ 更新连续天数
→ 下一日任务
→ 结营
```

连续2天未完成：提醒；连续4天：推荐补课/降低难度，并可产生运营任务。

## 12.3 直播

```text
预约 → 开播提醒 → 进入 → 参与 → 结束 → 回放 → 训练记录
```

# 13. 商城

## 13.1 分类

瑜伽垫、瑜伽砖、瑜伽带、服饰、毛巾、水杯及训练生活方式商品。

## 13.2 商品详情

必须说明：规格、库存、售价、会员价、训练场景、售后。

## 13.3 商品关联

课程/训练计划结束后可推荐训练所需商品，例如：

> “你正在做柔韧训练，瑜伽砖可以帮助降低动作难度，适合居家训练。”

## 13.4 购买

```text
SKU
→ 数量
→ 地址
→ 服务端报价
→ 创建订单
→ 支付
→ 扣库存
→ 待发货
→ 发货
→ 收货
→ 完成
```

库存必须原子扣减，订单必须幂等。

# 15. 购物车/订单/售后

订单状态：

```text
待支付 → 已支付 → 待发货 → 已发货 → 已完成
             ↓
          退款中 → 已退款
```

售后：

```text
提交申请
→ 审核
→ 同意/拒绝
→ 退货
→ 退款
→ 完成
```

用户必须看到每次状态变化及原因。

# 18. 运营触发规则

用户端行为可以触发管理端任务：

| 事件 | 管理端任务 |
|---|---|
| 体验课完成未购买 | T+0跟进 |
| 14天未训练 | 召回 |
| 7天到期 | 续费 |
| 低评分 | 客诉回访 |
| 私教剩20% | 续购复盘 |
| 训练计划连续4天未完成 | 关怀 |
| 商品售后 | 售后处理 |

这保证用户端不是孤立产品。

# 19. 关键异常

## 支付成功权益未到账

用户：
> “订单已支付，权益正在同步，请稍候。”

后端异步补偿，运营端出现异常订单任务。

## 名额被抢

> “名额刚刚被其他会员预约，请重新选择。”

## 商品缺货

> “该规格刚刚售罄，可以看看其他规格。”

## 课程取消

> “很抱歉，本场课程因门店原因取消，您的权益已恢复。”

## 网络失败

保留用户选择，不清空表单，提供重试。

# 21. 验收定义

每个功能必须同时完成：

```text
UI
+ 交互
+ API
+ 状态机
+ 异常
+ 权限
+ 幂等
+ 数据流水
+ 埋点
+ 消息
+ 运营触发
+ 验收用例
```

## 预约验收

- 100人抢10个名额只能成功10人。
- 同一人重复点击不能产生两条预约。
- 取消后名额正确释放。
- 签到一次只能消课一次。

## 支付验收

- 前端修改价格无效。
- 支付回调重复执行不能重复发权益。
- 订单状态最终一致。

## 数字训练验收

- 重复点击完成不能重复积分。
- 计划进度与任务记录一致。

## 商品验收

- 并发下单不出现负库存。
- 订单金额可追溯。
