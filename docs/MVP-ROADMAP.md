# V8 MVP 路线

## 目标

不是把所有 PRD 做完，而是验证一家瑜伽馆是否可以通过 Yoga 提高留存、客单价和增购。

## Phase 0：工程骨架

- Spring Boot Modular Monolith
- MySQL / Redis / Object Storage
- 统一认证
- API / Error / RequestId
- 数据库迁移
- Audit / Outbox
- CI

**出口标准：** 后端可以启动、迁移数据库、完成健康检查和一条端到端 API 流程。

## Phase 1：交易与履约

```text
登录
 ↓
会员
 ↓
课程/排课
 ↓
预约
 ↓
支付
 ↓
权益授予
 ↓
签到
 ↓
权益核销
```

P0 必须打通：

- 用户登录
- 会员
- 会员产品
- 课程
- 排课
- 预约/取消
- 签到/消课
- 订单
- 支付
- Entitlement

**出口标准：** 一个真实会员可以完成“购买 → 预约 → 到店 → 签到 → 消课”。

## Phase 2：单店经营与 LTV

重点建设当前人力能够运营起来的线下经营能力：

- 体验课 CRM
- 续费
- 沉默召回
- 私教
- 精品小班
- 商品/SKU/库存
- 商品套餐
- Event → Rule → Task
- 基础经营数据
- Next Best Action 规则推荐
- 推荐有礼
- 工作坊等线下增收产品

**明确：本阶段不做数字课程、不要求内容生产、不做复杂直播。**

**出口标准：** 系统每天能产生可执行经营任务，并能统计任务对训练、续费、客单价和收入的影响。

## Phase 3：数字课程与线上增收

当门店已经具备稳定会员、课程体系、教练团队和内容运营能力后，再进入数字化增收阶段。

建设：

- 7/14/21 天训练计划
- 录播数字课程
- 数字内容版本管理
- 训练计划权益
- 直播/训练营
- 数字课程与线下课程联动

数字课程的产品化路径：

```text
线下高需求课程
      ↓
持续验证
      ↓
标准化课程方法
      ↓
录制
      ↓
数字课程
      ↓
线上增收
```

**原则：先验证，再内容化；不为了“有数字课程”而提前消耗运营人力。**

**出口标准：** 至少验证一个“线下训练 → 数字产品 → 增购/续费”的闭环。

## Phase 4：规模化

在单店模型已经验证后再考虑：

- SaaS
- 多门店
- 多租户
- 企业瑜伽
- Retreat
- 联盟
- AI 推荐
- 微服务化

## 暂停项

在 Phase 3 之前暂停：

- 数字课程
- 复杂直播体系
- 大规模内容生产体系

在单店模型验证之前暂停：

- SaaS
- 多门店
- 多租户
- 企业瑜伽
- Retreat
- AI 推荐
- 微服务
- 复杂 ERP

## 关键指标

### 用户

- 体验课到店率
- 体验转会员率
- 30 日训练留存
- 14 日沉默率

### 商业

- ARPU
- 会员续费率
- 私教/小班渗透率
- 商品连带率
- 会员 LTV
- P3 数字产品购买率

### 运营

- 任务完成率
- 召回成功率
- 推荐点击率
- 推荐转化率

## 最终验收

```text
真实门店
 ↓
真实会员
 ↓
真实课程
 ↓
真实支付
 ↓
真实训练
 ↓
真实增购
 ↓
真实续费
 ↓
P3：数字产品增购
```

只有当线下单店经营链路跑通，才进入数字课程和规模化设计。
