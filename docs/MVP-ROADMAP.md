# V8 MVP 路线

## 目标

不是把所有 PRD 做完，而是验证一家瑜伽馆是否可以通过 Yoga 提高留存、客单价和增购。

## Phase 0：工程骨架

- Spring Boot Modular Monolith
- MySQL / Redis / Object Storage
- 统一认证
- API / Error / RequestId
- 数据库迁移
- Audit / Outbox
- CI

**出口标准：** 后端可以启动、迁移数据库、完成健康检查和一条端到端 API 流程。

## Phase 1：交易与履约

```text
登录
 ↓
会员
 ↓
课程/排课
 ↓
预约
 ↓
支付
 ↓
权益授予
 ↓
签到
 ↓
权益核销
```

P0 必须打通：

- 用户登录
- 会员
- 会员产品
- 课程
- 排课
- 预约/取消
- 签到/消课
- 订单
- 支付
- Entitlement

**出口标准：** 一个真实会员可以完成“购买 → 预约 → 到店 → 签到 → 消课”。

## Phase 2：经营闭环

- 体验课 CRM
- 续费
- 沉默召回
- 私教
- 精品小班
- 商品/SKU/库存
- 基础数字课程
- Event → Rule → Task

**出口标准：** 系统每天能产生可执行经营任务，并能统计任务对训练、续费和收入的影响。

## Phase 3：LTV 增长

- 训练计划
- 商品套餐
- Next Best Action 推荐
- 推荐有礼
- 直播/训练营
- 工作坊

**出口标准：** 至少验证一个“训练 → 推荐 → 增购”的闭环。

## 暂停项

以下不进入单店 MVP：

- SaaS
- 多门店
- 多租户
- 企业瑜伽
- Retreat
- AI 推荐
- 微服务
- 复杂 ERP

## 关键指标

### 用户

- 体验课到店率
- 体验转会员率
- 30 日训练留存
- 14 日沉默率

### 商业

- ARPU
- 会员续费率
- 私教/小班渗透率
- 数字产品购买率
- 商品连带率
- 会员 LTV

### 运营

- 任务完成率
- 召回成功率
- 推荐点击率
- 推荐转化率

## 最终验收

```text
真实门店
 ↓
真实会员
 ↓
真实课程
 ↓
真实支付
 ↓
真实训练
 ↓
真实增购
 ↓
真实续费
```

只有当这条链路跑通，才进入规模化设计。
