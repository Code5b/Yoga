# Yoga V2 业务 Pattern

## 用户端信息优先级

首页：上课提醒/待完成训练 → 会员权益 → 今日课程 → 推荐 → 活动/商城。

## Course → Booking

课程卡 → 课程详情 → 服务端资格校验 → 预约确认 → 支付（如需）→ 预约成功 → 提醒 → 签到 → 消课 → 训练记录。

课程卡必须支持：可预约 / 已预约 / 已满 / 候补 / 已结束 / 无权益 / 时间冲突。

## Membership → Renewal

会员状态 → 剩余权益 → 到期风险 → 个性化续费方案 → 订单 → 支付 → 权益发放。

状态视觉必须区分正常、次数不足、7天到期、已到期。

## Training → Recommendation

训练完成 → 更新计划进度 → 连续训练 → 积分 → 推荐下一课。

推荐必须显示理由，例如“最近 14 天未训练”“你正在练习柔韧性”。

## Course → Product

课程/训练目标 → 商品场景推荐 → 商品详情 → SKU → 订单 → 库存 → 售后。

商品推荐不能伪装成广告，要解释与当前训练的关系。

## Admin Event → Task

业务事件 → 系统判断 → 创建任务 → KMP 提醒 → 员工查看会员画像 → 执行动作 → 选择结果 → 下一次跟进 → 关闭 → 统计。

任务优先级：P0 今天必须完成、P1 48小时、P2 本周、P3 观察。

## Mobile interaction

优先使用 Bottom Sheet、Sticky Action、Inline Feedback、Skeleton、Toast、Confirmation，而不是复杂桌面弹窗。管理端只做移动端，不做 Web 后台。

## P3 boundary

数字课程、训练计划内容管理、直播/训练营属于 P3；当前 P0/P1/P2 设计只保留必要的信息架构兼容，不把数字课程作为当前核心导航。
