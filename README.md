# Yoga 单店瑜伽馆经营与会员增长系统

> **当前版本：V8.0**  
> **阶段：单店 MVP → 工程化落地 → 单店经营模型验证**  
> **更新时间：2026-08-19**

Yoga 不是简单的瑜伽约课系统，而是一套围绕单店瑜伽馆建立的 **“训练 + 会员运营 + 多收入模型”** 系统。

核心飞轮：

```text
训练
 ↓
行为数据
 ↓
会员画像
 ↓
下一步推荐
 ↓
增购/续费
 ↓
更多训练
 ↓
更完整的数据
```

## 1. 当前边界

第一阶段只服务一家门店：

- 用户端：uni-app / 微信小程序
- 管理端：KMP / Compose Multiplatform
- 后端：Spring Boot
- 数据：MySQL + Redis + 对象存储

当前明确不做：SaaS、多门店、多租户、Web 管理后台、复杂 ERP、开放平台、微服务。

> **先把一家店的经营模型跑通，再谈规模化。**

## 2. V8.0 核心原则

1. **Entitlement（权益）是核心领域抽象**：会员卡、私教、小班、数字课程、训练计划最终都转化为可核销/可访问权益。
2. **Order 是统一交易入口**：会员、服务、数字产品、实物商品、套餐都使用统一订单模型。
3. **Event → Rule → Task**：会员行为产生事件，规则产生经营动作，动作形成可执行任务。
4. **推荐先规则化**：第一阶段不做 AI 推荐，先建立可解释、可运营的规则引擎。
5. **版本化数字内容**：已购买训练计划的历史版本不能被后续修改破坏。
6. **状态机优先**：预约、订单、支付、权益、退款、库存等关键业务必须显式定义状态迁移。
7. **单店 MVP 优先**：所有功能必须回答“是否直接帮助单店经营验证”。

## 5. 开发优先级

### P0：交易与履约基础

登录、会员、会员产品、课程排课、预约、取消、签到、消课、订单、支付、权益。

### P1：单店经营

体验 CRM、运营任务、续费、沉默召回、私教、小班、商品、库存、基础数字课程、基础数据。

### P2：提高 LTV

训练计划、商品套餐、推荐有礼、规则推荐、直播/训练营、工作坊。

### 暂停

SaaS、多店、企业瑜伽、Retreat、AI 推荐、微服务化。

## 6. 完成定义

业务功能不是“页面完成”即完成，必须同时具备：

```text
UI + API + Domain Rule + State Machine + Idempotency
+ Permission + Transaction + Event + Audit + Analytics + Acceptance Tests
```
