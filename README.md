# Yoga 单店瑜伽馆经营与会员增长系统

> **当前版本：V8.1**  
> **阶段：单店 MVP → 单店经营模型验证 → P3 数字化增收**  
> **更新时间：2026-08-19**

Yoga 不是简单的瑜伽约课系统，而是一套围绕单店瑜伽馆建立的 **“训练 + 会员运营 + 多收入模型”** 系统。

核心飞轮：

```text
训练
 ↓
行为数据
 ↓
会员画像
 ↓
下一步推荐
 ↓
增购/续费
 ↓
更多训练
 ↓
更完整的数据
```

## 1. 当前边界

第一阶段只服务一家门店：

- 用户端：uni-app / 微信小程序
- 管理端：KMP / Compose Multiplatform
- 后端：Spring Boot
- 数据：MySQL + Redis + 对象存储

当前明确不做：SaaS、多门店、多租户、Web 管理后台、复杂 ERP、开放平台、微服务。

> **先把一家店的经营模型跑通，再谈规模化。**

## 2. V8.1 核心原则

1. **Entitlement（权益）是核心领域抽象**：会员卡、私教、小班等线下权益统一进入履约体系。
2. **Order 是统一交易入口**：会员、服务、实物商品、套餐使用统一订单模型；数字产品在 P3 再接入。
3. **Event → Rule → Task**：会员行为产生事件，规则产生经营动作，动作形成可执行任务。
4. **推荐先规则化**：P2 先建立可解释、可运营的规则引擎，不做 AI 推荐。
5. **数字课程 P3 再做**：当前人手不足，不提前建设内容生产和直播体系；先把线下经营基本盘做好。
6. **状态机优先**：预约、订单、支付、权益、退款、库存等关键业务必须显式定义状态迁移。
7. **单店 MVP 优先**：所有功能必须回答“是否直接帮助单店经营验证”。

## 5. 开发优先级

### P0：交易与履约基础

登录、会员、会员产品、课程排课、预约、取消、签到、消课、订单、支付、权益。

### P1：单店经营基本盘

体验 CRM、续费、沉默召回、私教、小班、商品、库存、基础经营数据、运营任务。

### P2：运营自动化与 LTV 增长

Event → Rule → Task、规则推荐、商品套餐、推荐有礼、工作坊等线下增收产品。

**P1/P2 明确不做数字课程。**

### P3：数字课程与线上增收

7/14/21 天训练计划、录播数字课程、内容版本管理、训练计划权益、直播/训练营，以及线上线下联动。

数字课程必须建立在已经验证成功的线下课程之上：

```text
线下验证 → 标准化 → 录制 → 数字化 → 线上增收
```

### P4：规模化

在单店模型验证后再考虑 SaaS、多店、多租户、联盟、企业瑜伽、AI 和微服务化。

## 6. 完成定义

业务功能不是“页面完成”即完成，必须同时具备：

```text
UI + API + Domain Rule + State Machine + Idempotency
+ Permission + Transaction + Event + Audit + Analytics + Acceptance Tests
```
