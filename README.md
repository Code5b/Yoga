# Yoga 单店瑜伽馆经营与会员增长系统

> **当前版本：V6.0**  
> **更新时间：2026-08-19**  
> **产品阶段：单店**

Yoga 不是单纯的瑜伽约课工具，而是一套帮助单店瑜伽馆完成 **获客 → 体验 → 转化 → 训练 → 提升客单 → 复购 → 转介绍** 的经营系统。

## 一、产品定位

```text
获客
 ↓
体验课
 ↓
会员
 ↓
团课
 ↓
精品小班 / 私教 / 体态评估
 ↓
训练计划 / 数字课程 / 直播
 ↓
瑜伽商品
 ↓
VIP / 续费
 ↓
推荐好友
 ↓
新客
```

产品核心不是“卖更多课程”，而是帮助门店经营会员生命周期，提高：

- 体验转化率
- 会员活跃率
- 客单价
- ARPU
- 续费率
- LTV
- 商品购买率
- 数字课程购买率

## 二、技术边界

项目只使用以下技术栈：

| 端/层 | 技术 | 说明 |
|---|---|---|
| 用户端 | uni-app | 微信小程序为第一优先级 |
| 管理端 | Kotlin Multiplatform / Compose Multiplatform | **只做移动管理端，不做 Web 后台** |
| 后端 | Spring Boot | 业务 API、支付、任务、运营、数据 |

当前明确不做：

- SaaS
- 多门店
- Web 管理后台
- 开放平台
- 复杂 ERP
- 大规模供应链

## 五、开发原则

1. **先单店，先跑通经营闭环。**
2. **运营优先，每个重要数据都必须能够产生行动。**
3. **先验证，再重投入。** 数字课程先 MVP，商品先少 SKU。
4. **服务与商品联动。** 商品围绕训练场景推荐，而不是做独立杂货商城。
5. **数字课程不是视频仓库。** 核心是训练计划、打卡、直播和结果。
6. **KMP 管理端不是缩小版 Web 后台。** 它围绕“今天应该做什么”设计。
7. **商业模式、PRD、SOP 必须一致。** 每一个收入目标都必须能落到具体产品和运营动作。

## 六、版本路线

### P0：能开店

会员、会员卡、课程、排课、预约、签到、订单、支付。

### P1：能经营

体验 CRM、运营任务、私教、小班、商品、积分、数据、基础数字课程。

### P2：能增长

训练计划、直播、训练营、工作坊、个性化推荐、商品套餐。

### P3：长期扩展

Retreat、企业瑜伽、自有品牌、教练内容合作。
